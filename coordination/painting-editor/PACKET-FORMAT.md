# Проверяемые редакционные отправки

Отправка двухэтапная. Существующий модуль сохраняет неизменяемый исходный JSON в inbox и проверяет запись чтением коммита. GitHub Actions затем создаёт производные файлы в packets и отдельным коммитом публикует весь индекс. Подтверждение исходной записи не означает завершение разбиения.

Workflow индексирует существующие и новые исходники. Он имеет Contents: write на репозиторий, однако скрипт создаёт только производные файлы в coordination/painting-editor/packets, а git add ограничен этой папкой. Игровые данные, исходные отправки и браузерные правки не изменяются. Новый браузерный статус читает публичный индекс без токена.

Для каждого пакета используется папка по SHA-256 исходных байтов. manifest.json сохраняет sourcePath, sourceCommit первого добавления, sourceURL на исходник в этом коммите, sourceSHA256, всю корневую metadata без массива artists и полный упорядоченный список ID и файлов. sourceCommit каталога внутри исходного JSON остаётся в metadata: это не коммит отправки.

Обычное задание сохраняется отдельным компактным JSON. Неизвестные поля не отбрасываются, порядок заданий сохраняется. Пробелы производного JSON могут отличаться, значения полей сравниваются через deepEqual. Исходный файл не переписывается, и его SHA-256 сверяется с именем и историей Git.

Задание более 7500 байт кодируется в независимые base64-части по 8192 исходных байта; его JSON-дескриптор содержит порядок и хеши частей. Это не обрезка текста: проверка собирает байты, сверяет SHA-256 и сравнивает восстановленный объект с исходным. Максимум производного файла 16000 байт. При превышении лимита индекса, повреждении, неполном задании, повторном ID или конфликте workflow завершается ошибкой, не публикуя частичный индекс.

Повторный запуск идемпотентен. Существующие конфликтующие производные задания не перезаписываются. Общий index.json обновляется только после проверок всех исходников. Поле verified означает проверку структуры и сохранности данных, а не историческую достоверность содержания или завершение статьи. totalArtists считает записи отправок; повторные редакции одного художника в разных пакетах могут учитываться отдельно.

Проверки: node tools/test-painting-packet-index.cjs. Предварительный аудит без записи: node tools/painting-packet-index.cjs. Создание производных файлов: node tools/painting-packet-index.cjs --write. Требуется полный Git history.
